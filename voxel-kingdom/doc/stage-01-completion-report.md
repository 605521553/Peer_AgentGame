## 4. 自动化与协议结果

Python 测试：**38 passed**。Godot 网格检查：**6 项通过**。原生客户端：实际进入独立房间，创建并渲染一栋建筑，确认 `gl_compatibility` / `opengl3`。

覆盖的主要行为：

- 非法模型：负坐标、尺寸越界、颜色格式错误、颜色索引错误、重复方块、空模型与展开量超限。
- 权限：伪造归属字段、跨房间操作、修改 / 拆毁另一玩家建筑与无权限蓝图复用均拒绝。
- 原子性：占地冲突或模型更新失败不改变原建筑；拆除与销毁释放占地和预算。
- 幂等：相同 ID 相同内容执行一次；相同 ID 不同内容拒绝；聊天重试不再次调用或创建。
- 并发一致性：新玩家快照衔接有序事件；迟到 AI 输出不能覆盖已改变的修订号。
- 恢复：SQLite 重开后世界和身份仍可恢复；中断聊天恢复原提交结果或标记未执行。
- 资产缓存：已有资产的后续事件不重复携带模型，删除后再次生成可正确重新下发。
- AI 格式：空响应、截断、非法 JSON 与超时不执行；模拟实际请求检查完整规则和密钥未进入提示。
- 无损上下文压缩：为 AI 压缩的长方体蓝图展开后内容哈希与原模型一致。

测试依赖产生一条 Starlette TestClient 的 httpx 弃用提醒；本次断言均通过。浏览器验收记录的页面控制台错误为 0。

## 5. 真实 DeepSeek 结果

通过实际 DeepSeek API 完成以下三步，而非固定模型响应：

| 操作 | 结果 | 模型调用耗时 |
| --- | --- | --- |
| 自然语言生成灰墙蓝顶四塔城堡 | 创建成功，模型尺寸 12 × 10 × 12，276 个实心体素，616 个未合并外露面 | 8.454 秒 |
| 仅修改选中方块为 `#FF00CC` | 成功，仅局部坐标 `[0,0,0]` 的颜色发生变化，形状和其余颜色保留 | 2.680 秒 |
| 主动销毁己方城堡 | 成功，实例移除，占地释放 | 1.897 秒 |

这次三步完整请求约 13.2 秒，每步一次模型调用。随后通过网页聊天表单实际创建绿色单体素建筑，并验证其他玩家收到变化。

联调中曾出现模型字段错误、颜色索引错误和连接超时，均没有执行非法世界修改。最终采用更明确的格式说明、一次纠错、无损模型压缩与可复用的 HTTP 连接；简单单方块改色使用独立命令，减少整模型重写。调用耗时是本次样本，不作为所有未来生成请求的保证。

## 8. 性能结果

单客户端、Release Web、同一 Intel UHD 770 环境：

| 指标 | 常规场景 | 接近 / 达到房间预算的多彩场景 |
| --- | --- | --- |
| 建筑数量 | 20 | 64 |
| 每栋体素 | 2,188 | 2,048，每方块不同色 |
| 总体素 | 43,760 | 131,072，达到上限 |
| 未合并外露面总量 | 48,800 | 65,536，达到上限 |
| 15 次稳态 FPS 采样平均 | 60.0 | 59.2 |
| FPS 最低采样 | 60 | 56 |
| 采样中最大帧时间 p95 | 16.67 ms | 18.74 ms |
| 加入后全部建筑渲染就绪 | 3.89 秒 | 1.79 秒 |
| HTTP 命令总往返 p95 | 49.30 ms | 60.83 ms |
| 页面脚本错误 | 0 | 0 |

“加入后就绪”从已加载引擎的网页点击进入房间开始，包含快照与模型构建，不包含首次下载 WASM。基准建筑复用共享蓝图与网格，不能据此推断 64 个完全不同高复杂度模型也有相同加载时间。

GPU 监视器的 primitive / Draw Calls 包含阴影等绘制通道与场景内容，不等于建筑模型的单次几何面数。两个浏览器在同一机器同时渲染会竞争 GPU，双客户端测试的即时 FPS 较单客户端基准低，报告分别保存二者结果。

Release 的静态内存监视器未提供可用读数，已用 `null` 表示未知，没有把 0 当作真实内存消耗。峰值内存、弱网首次加载、手机与 Safari 性能尚未测量。

## 9. 关键实现差异

- 使用随机强会话 token 与服务端哈希记录绑定身份，当前没有完整账号系统。
- 原计划只使用完整模型替换；增加 `building.paint_voxel`，使精确单点改色可以直接验证与执行。
- 初版模型更新重新生成该建筑的局部块；尚未做仅重建改变块的细粒度差分路径。
- HTTP 与 HTTPS 由一个进程提供，避免两个权威进程各自缓存导致世界不一致。
- LAN 使用自签证书，公网有效域名证书与托管部署按最新范围后续开展。

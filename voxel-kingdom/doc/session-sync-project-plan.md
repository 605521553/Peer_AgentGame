# 会话恢复、传输优化与客户端/服务端分项目实施方案

日期：2026-10-15。本文保留实施前的方案与基线描述；现已实施并部署，实际结果以 [完成情况与验收报告](session-sync-completion-report.md) 和 [逐批记录](session-sync-implementation-log.md) 为准。

## 目标与复杂度取舍

1. 避免重复快照、重复模型、单方块改色后的整模型传输。
2. 同一浏览器有效会话刷新后自动恢复身份、房间和相机，进入游戏。
3. 同一仓库下形成独立客户端/服务端子项目，单独构建测试，统一协议与兼容性管理。

采用“小型权威元数据快照 + 按需模型资产 + 在线变化事件”。当前房间最多 64 栋建筑，初次进入/重连下发一次完整实体清单通常足够小，不实现任意历史事件回放。服务器仍可展开、规范化、验证并保存完整世界；本轮主要优化传输与恢复，不更换 SQLite 或引入消息中间件。

## 当前项目组织

- 根目录是 Godot 项目：project.godot、scenes/、scripts/、export_presets.cfg。
- web/ 是浏览器页面、聊天交互、网络连接；它与 Godot 共同构成客户端，而不是服务器子项目。
- backend/ 是 Python 权威服务器，包含规则、验证、SQLite、DeepSeek、API 与 WSS。
- tools/ 混放导出、运行、部署及验收工具；tests/ 混放 Python 和 Godot 验证。
- Godot Web 导出通过排除规则避免打包后端、测试、文档等；正式公网 Nginx 提供静态客户端，代理 API/WSS 到独立 Python 进程。
- 当前部署脚本统一打包 backend、web、build/web、deploy；改网页也走整个发布流程并重启后端。逻辑运行职责已分开，目录、构建及发布管理还没有完全分开。

```text
  deploy/
  tools/                  # 跨项目部署、端到端验收
  doc/

  build/client-web/
```

仍保持一个仓库，避免两个仓库之间反复同步协议和兼容提交。client/server 各有说明、依赖、入口、测试和构建；protocol 是单一协议来源，不是共享执行权限逻辑的第三个应用。服务器读取或在打包时复制这份规则，客户端只需要公开协议；服务端权限实现与密钥继续私有。

目录迁移必须同步修正资源路径、模型规则路径、导出脚本、静态资源路径、测试导入、部署白名单及 README。保持原有 SQLite 和会话不变。客户端单独发布无需重启服务端；服务端单独发布无需重新导出 WASM。新旧协议不兼容时使用协调发布，不能因为允许独立发布而忽略兼容性。

## 传输方案

### 清晰分离模型、实例与变化

- 模型资产：内容 ID、尺寸、调色板和体素表示；本地按模型 ID 缓存。
- 建筑实例：ID、模型 ID、位置、朝向、拥有者、名称、revision。
- 状态变化：创建/修改/删除事件及 seq，必要时包含局部体素补丁。

继续 JSON，优先减少重复和无效内容。模型支持当前 cells_v1 与 box_ops_v1 的无损传输；服务端验证后按编码长度择优，客户端增加有预算限制的盒子解码。模型内容 ID 基于规范体素定义，不因传输格式选择而变化。暂不增加二进制、八叉树或复杂通用压缩框架。

### 初次进入 / 刷新 / 重连

1. HTTP 加入/恢复接口只返回身份、房间和协议信息，不返回完整世界模型。
2. WSS 认证带 token 和有界的本地已知模型 ID 列表；服务器校验身份。
3. 在房间锁保护的一致性边界内，取得当前元数据快照并注册后续订阅；初始消息携带实体清单、玩家清单、seq、规则版本及缺失模型。
4. 本地已有模型直接复用；缺失模型由服务器补齐。只发送该房间实际引用且客户端缺失的资产，不信任客户端声明为权限依据。
5. 在线继续接收 seq 有序事件；断档则重新同步清单和缺失模型，不做无上限事件追赶。

列表声明应有数量和字节上限，按当前房间资产筛选，防止持久缓存增长后把所有历史模型 ID 上传。缓存失效或无法读取时，诚实声明没有缓存，正常恢复所有必要模型。

实体清单仍是一次小型“全量”，这是有意的取舍；避免为了几 KB 元数据引入复杂 diff 计算，重点减少体素模型和重复响应。

### 命令结果与状态广播

HTTP 命令/AI 回执仅保留 command_id、status、seq、目标 ID/revision、错误和 AI 说明等必要信息，不再附带完整模型事件；WSS 是正常状态更新通道。

保留幂等查询和回执确认。收到成功回执但 WSS 尚未达到对应 seq 时等待同步；若连接丢失，恢复同步。不能为了去重而丢失确认操作最终是否执行的能力。

### 局部变化

单格改色下发目标实体、基础/新 revision、格子坐标、新 RGB 和新模型 ID。客户端在匹配的旧模型上应用补丁；错版或缺少基础模型时回退获取最新模型。补丁避免依赖会被规范化重排的调色板下标。

大范围导入或形状替换允许发送完整新模型，不先做任意模型的昂贵全量差分算法。新模型按内容复用；未变模型不重复发送。销毁只发实体 ID/版本。AI 仍每次携带完整规则，但修改单格使用已支持的小命令；保留必须的上下文，避免为省数据丢掉编辑语义。

## 登录与本地缓存

### 自动会话恢复

启动读取上次房间和 token → 自动验证 → 连接 WSS → 自动显示场景。身份有效不显示登录框，不再填写邀请码，也不新建玩家槽位。

鉴权失败才回到登录；网络故障显示重试，不清除仍可能有效的会话。切换房间和主动退出有明确入口。当前 token 存储方式先沿用，避免同时引入全新账号体系；服务端不依赖缓存身份字段判断权限。

### 缓存范围

- localStorage：已有会话、上次房间、按房间区分的相机状态。
- IndexedDB：模型资产，按内容 ID 和格式版本保存，异步读写，有容量/清理策略。
- 房间实体清单：第一版刷新后向服务器获取最新的小快照，不先持久化整份离线世界。

这是比“缓存整个世界、先显示旧状态、再回放所有事件”更简单的实现：已有体素模型可直接从本地加载，只需要等待一次小型状态同步。当前用户目标是自动进入原场景，不要求断网也能预览旧世界，所以暂不增加离线快照和离线编辑。

浏览器清理存储、配额不足或 IndexedDB 不可用时，降级到内存缓存与正常服务器恢复。模型校验失败则删除并重新获取；不能因此阻止玩家进入。

相机位置/缩放/旋转保存并恢复。刷新仍会初始化 Godot 与 GPU 资源，但不会重复下载已知模型。运行中的重同步按实体 revision/model ID 对比，只更新有变化的节点，避免全场重建。

## 静态资源与发布

HTML 与启动清单及时验证更新；WASM/PCK 等使用构建版本 URL 或内容指纹再配置长期缓存，不能给固定文件名直接永久缓存。协议版本明确，发现不兼容客户端给出刷新提示。客户端缓存只作为加速，服务器始终可提供完整恢复数据。

静态资源缓存与模型缓存分开测量；当前首屏 WASM 压缩后约 10 MB，而多数建筑模型只有几 KB。必须记录下载、引擎初始化和模型构建耗时，不把所有等待归因于场景传输。

## 分批实施与验收

| 批次 | 实施内容 | 验收 |
|---|---|---|
| A | 自动会话/视角恢复，错误分流 | 刷新无需输入/点击；身份、房间、建筑和视角恢复；无额外玩家槽位 |
| B | HTTP/WSS 去重、轻回执、局部改色补丁 | 一次初始化；改单格不带整模型；断档、错版可恢复 |
| C | IndexedDB 模型缓存、缺失资产协商、紧凑编码 | 已缓存模型刷新不重传；新增/修改/删除正确；清缓存也能进入 |
| D | client/server 子项目整理、独立构建部署 | 两端独立测试构建；客户端单独发布不重启后端；端到端回归 |

每批代码、变更理由、测试结果、部署版本和未通过项追加到本地 Markdown。目录调整与协议改动分批验证，降低定位问题难度；完成后再在服务器协调部署。

关键故障用例：无效 token、网络失败、缓存损坏、配额不足、旧协议、离线期间删除/修改建筑、同形模型复用、服务重启。性能记录：HTTP/WSS 模型发送次数与字节数、刷新到场景可见/可操作耗时、重建模型数。不预先承诺绝对毫秒数或固定压缩比例。

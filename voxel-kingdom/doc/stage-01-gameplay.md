# 第一阶段：玩法与验证

> 版本：0.2 · 日期：2026-10-13 · 状态：本机 / 局域网版本已实施，验收结果见完成报告  
> 对应：[技术实施计划](stage-01-implementation.md) · 上位：[完整玩法流程](game-design-overview.md)

## 1. 阶段目标

做出可在网页中多人使用的体素建造验证版本。玩家能通过上帝视角观察地图，向 DeepSeek 描述需求，在自己的区域创建有自定义形状和方块颜色的建筑，并进行修改、拆除和主动销毁。

本阶段验证“自然语言 → 规则理解 → 游戏操作 → 服务端校验 → 场景变化 → 多人一致”，不加入可移动单位、攻击、资源经济、施工时间和胜负。

## 2. 房间与基础规则

- 建议每房间先支持 2–4 名玩家，每人拥有一块明确标示的建造区域。
- 使用平坦的有限地图。玩家看得到全图和其他人的建筑，但只能创建、修改与拆毁自己的建筑。
- 建筑立即生成；没有资源费用和等待时间。
- 建筑必须在地图与己方区域内，不与已有建筑占地冲突，且至少有底部方块接触地面。
- 为便于首版验证，建筑按整个外接矩形预留占地，庭院和洞口不允许另放一栋建筑；不模拟结构承重。
- 方块采用不透明 RGB 颜色，每个方块可以不同；透明和动态材质后续加入。
- 玩家可以重新着色或替换已有建筑的体素模型；修改不应意外产生新建筑或改变归属。
- 尺寸、方块数、建筑数和房间容量有上限，超限时明确说明原因。具体数值集中在技术实施计划。

## 3. 观察与操作界面

游戏提供倾斜俯视的上帝视角，支持平移、缩放与绕地图旋转。建议以正交投影起步，便于观察占地与比较尺寸。

界面显示地图方位、网格坐标、玩家建造区域、所选建筑名称与归属。点击地面可以标记建造位置，点击建筑可以让后续“这座建筑”引用明确对象。

网页包含聊天输入、调用进度和操作结果。AI 生成中不会阻塞视角和其他玩家的操作；合法且意图明确的单项建筑操作默认自动执行，并展示摘要，无须每次额外确认。

## 4. 玩家操作流程

### 4.1 创建建筑

1. 进入房间，看到自己的建造区域。
2. 点击区域内的位置，输入：“在这里创建一座灰墙蓝顶的小城堡，有四座塔和一个门洞。”
3. 每次调用 DeepSeek 都附带当前完整游戏规则、可用操作和相关场景信息。
4. AI 生成操作方案，游戏检查尺寸、颜色、占地与归属。
5. 合法则创建建筑并同步给其他玩家；非法则保持场景不变并反馈原因。

这里的“完整规则”指本房间当前阶段的全部生效规则，无须附带未来未开放的战斗玩法。

### 4.2 修改形状与颜色

选中自己的城堡，输入“保持其他部分，把塔顶改成红色”，或“给这座建筑加一座侧塔”。成功时修改原建筑，其他玩家看到同一结果；新尺寸冲突或超限时，原建筑保留。

颜色验证必须包括相邻方块不同颜色、一个指定方块单独变色和大量不同颜色，不能只验证整栋建筑统一换色。

### 4.3 拆除与主动销毁

“拆除这座建筑”立即移除己方建筑并释放占地；“销毁这座建筑”产生简短销毁反馈后移除显示，同样释放占地。第一阶段不保留需要清理的可交互残骸。

拆除与销毁均要求归属为当前玩家。请求“直接拆掉另一个玩家的城堡”被拒绝，不能造成世界变化。

### 4.4 查询、歧义与失败

可以询问“我有哪些建筑”“这座建筑属于谁”“这里还能放多大的建筑”。对象不明确或缺少位置时，AI 提示选择对象或补充信息，不随机拆除建筑。

超过限制、目标消失、连接中断或 AI 输出不完整时给出可理解的提示。AI 的解释以服务端结果为准，不能在操作被拒绝时说“已经建好”。

## 5. 多人体验

两位玩家在不同浏览器同时进入同一房间。各自的视角和选择独立，建筑变化共享。后加入者看到当前建筑与颜色；短暂断线重连后恢复到最新状态。

切换网页标签后回来，也能恢复连接和场景。第一阶段房间没有战争时间限制，不做离线战斗。

## 6. 玩法验收

| 编号 | 操作 | 应看到的结果 |
| --- | --- | --- |
| G01 | 平移、缩放、旋转，选择地面与建筑 | 视角稳定，位置与对象清楚，聊天不误触游戏操作 |
| G02 | 描述有塔楼、空心庭院和门洞的建筑 | 造型按有效需求生成；洞口为空，放置位置正确 |
| G03 | 指定不同方块颜色，再修改一个方块 | 相邻颜色边界清楚；其他方块颜色不变 |
| G04 | 修改已有建筑形状 | 原实例更新，归属与名称保持；其他玩家同步看到变化 |
| G05 | 创建超大建筑或放到区域外 / 冲突位置 | 拒绝并说明原因，已有世界保持不变 |
| G06 | 拆除、主动销毁自己的建筑 | 正确对象消失，占地释放；销毁有相应反馈 |
| G07 | 请求拆毁另一位玩家的建筑 | 拒绝，另一位玩家建筑不受影响 |
| G08 | 两人同时创建、修改建筑 | 双方最终建筑、位置、归属与颜色一致 |
| G09 | 刷新、后加入、断线重连 | 获得当前房间场景，不重复生成建筑 |
| G10 | DeepSeek 请求失败或输出无效 | 清楚反馈，场景继续响应，没有半栋建筑 |
| G11 | 提供意图明确的一次建造请求 | 自动执行并记录结果，不因额外确认打断常规操作 |
| G12 | 部署网页并在两台设备访问 | 完成对话、创建、修改与拆除的完整流程 |

全部玩法验收和对应技术检查通过后，才将第一阶段标记为完成。

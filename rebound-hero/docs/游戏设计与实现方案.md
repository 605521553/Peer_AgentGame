## 1. 核心定位

一款固定单屏、固定站位的 2D 弹射策略 Roguelike。玩家通过鼠标选择射击角度，利用墙壁和几何障碍物反射子弹，以尽量少的射击次数消灭敌人；清场后购买装备，形成不同构筑，最终击败最终 Boss。

核心体验有三项：

- **弹道策略**：观察几何结构，通过反弹寻找攻击路线。
- **随机构筑**：在伤害、预测能力、生存和特殊弹道之间分配有限金币。
- **重复挑战**：每局拥有不同的布局、敌人组合和商店选择。

最重要的差异化设计是：**弹道预测能力与伤害、生命一样，是可成长的核心属性。** 强化预测能直接改变玩家理解和规划关卡的能力。

不加入玩家自由移动、平台跳跃或持续自动射击。首版优先检验“观察 → 瞄准 → 反弹命中”的乐趣，再扩大内容规模。

## 2. 一局游戏与版本范围

```text
开始新局 → 生成并验证关卡 → 瞄准与预测
                           ↓
                      玩家发射
                           ↓
                    玩家弹丸全部结算
                           ↓
              有存活敌人 → 敌人反击 → 回到瞄准
                           ↓ 无存活敌人
                      奖励与商店
                           ↓
                         下一关

任意战斗阶段生命归零 → 失败统计 → 重开
最终 Boss 死亡且本轮弹丸结算完成 → 通关统计
```

| 内容 | 首个可玩版本 MVP | 完整版 |
| --- | --- | --- |
| 流程 | 5 个随机关卡，第 5 关完成后胜利 | 20 关，5/10/15/20 关 Boss |
| 障碍物 | 矩形、圆形、三角形 | 增加破坏墙、传送门等 |
| 敌人 | 普通、护盾反弹、射击敌人 | 强化变体、4 个 Boss |
| 武器 | 手枪、霰弹枪、子母弹枪 | 更多词条和机制组合 |
| 道具 | 预测、伤害、生命、护甲、分裂等小型池 | 完整流派与稀有机制 |
| 商店 | 4 商品位、购买、刷新、治疗、武器替换、强化 | 出售、更多服务与 Boss 奖励 |
| 存档 | 设置、局后统计 | 可选局内继续功能 |

不保留跨局金币、武器和强化。局内继续若加入，只恢复当前挑战，不形成永久战力成长。

## 3. 场景与操作

采用 1280×720 逻辑画布。建议战斗范围为 `(40, 80)` 至 `(1240, 660)`，顶部留给 HUD。玩家位于底部中央 `(640, 620)`，敌人主要分布于中上部，玩家周围设安全生成区。

战斗场景始终保留；下一关只替换内部内容。商店用 `CanvasLayer + Control` 覆盖战斗画面。

| 输入 | 行为 |
| --- | --- |
| 鼠标移动 | 计算枪口到鼠标的瞄准方向 |
| 左键 | 仅在瞄准阶段发射一次武器 |
| 数字键 1/2、滚轮 | 瞄准阶段切换两把武器 |
| 悬停商品/道具 | 查看效果、叠加规则和价格 |
| Esc | 暂停或关闭说明窗口 |

默认限制向上半平面发射，避免枪口立即撞上底墙；后续可通过试玩放宽。鼠标位于枪口附近时保留上一有效方向，避免零向量。

固定逻辑战场不随窗口比例扩大，优先使用等比例适配与留边。当前工程设置为 `canvas_items + expand`，实施时应调整，避免宽屏出现额外可战斗空间。

## 4. 回合与结算规则

### 4.1 状态机

使用 `RunController` 管理下列互斥状态：

| 状态 | 允许行为 | 退出条件 |
| --- | --- | --- |
| GENERATING | 生成、验证、准备物理碰撞 | 布局通过且碰撞就绪 |
| AIMING | 瞄准、切换武器、查看信息 | 成功接受发射输入 |
| PLAYER_RESOLVING | 播放玩家弹丸与分裂效果 | 活跃弹丸和待生成任务均为零 |
| ENEMY_WARNING | 显示存活攻击者的攻击预警 | 预警完成 |
| ENEMY_RESOLVING | 执行一次敌方齐射 | 敌方弹丸全部结算 |
| ROUND_END | 状态效果、死亡、清场判定 | 转入瞄准、商店或结局 |
| SHOP | 购买与管理装备 | 进入下一关 |
| VICTORY / DEFEAT | 统计与重开 | 玩家重开 |

暂停是独立标记，不混入战斗阶段。禁止多处脚本自行切换阶段。

### 4.2 明确规则

- 一次武器发射算一个玩家回合；霰弹和分裂弹不额外消耗回合。
- 玩家弹丸全部结束后，存活射击敌人各获得一次攻击机会；瞄准期间敌人不攻击。
- 最后一名敌人死亡时，仍须等待当前弹丸结束，才能清场；本轮不再触发新的敌人攻击。
- 玩家生命归零立即锁定失败，清理弹丸与待触发任务。若与最终敌人同一物理帧死亡，建议失败优先。
- 玩家弹丸通常不伤害玩家；护盾反射后的弹丸改为敌对弹丸，可以伤害玩家，但仍计入当前玩家弹丸结算阶段。
- 普通敌人受伤后默认吸收弹丸；穿透属于明确的特殊效果。护盾正面反射且不受伤，侧面和背面可受伤。
- 反弹指实际反射事件。允许 N 次反弹，即前 N 次反射继续飞行，第 N+1 次遇到反射面时销毁。

普通敌人不反击，因此没有直接时间压力；它承担教学和奖励作用。少射击奖励提供优化目标，后续混合敌人提供生存压力。

## 5. 弹道、碰撞与预测

### 5.1 物理规则

镜面反射：`v_new = v - 2 * dot(v, normal) * normal`。保持速度模长，伤害变化由装备控制。矩形使用面法线、圆形使用接触点径向法线、三角形使用对应边法线。

首版建议采用**中心点射线弹丸**：弹丸视觉有尺寸，命中以中心点为准。运行时每个物理帧对本帧移动距离执行射线扫描；预测也使用同一查询与反射函数。这样可优先保证预测与实际一致，并避免高速弹丸只靠位置重叠检测而穿墙。

Godot 的 `PhysicsDirectSpaceState2D.intersect_ray()` 可取得碰撞点与法线；物理空间查询放在物理更新中执行。参见官方[射线查询说明](https://docs.godotengine.org/en/stable/tutorials/physics/ray-casting.html)。

未来若需要具有真实半径的弹丸，应统一改为形状扫掠，运行和预测同时迁移。`CharacterBody2D.move_and_collide()` 也是可用的运动碰撞方案，但不能将其有限半径运动与中心射线预览直接混用，详见官方[物理介绍](https://docs.godotengine.org/en/stable/tutorials/physics/physics_introduction.html)。

### 5.2 每帧运行算法

```text
剩余距离 = 速度 × 物理帧时间
循环，直到剩余距离耗尽或触及本帧碰撞预算：
    查询当前位置到当前位置 + 方向 × 剩余距离
    无命中：前进至终点，结束
    有命中：扣除已走距离，调用统一碰撞规则
    若弹丸结束：注销并销毁
    若反射：按法线反射，增加反弹计数
    沿离开碰撞面的方向偏移微小距离，扣除偏移距离
    继续处理本帧剩余距离
```

连续近零距离碰撞时终止弹丸并记录诊断，避免卡在顶点。每帧碰撞循环达到预算时保留剩余路程，下一帧继续；不能直接穿过后续障碍物。敌人死亡后的碰撞关闭要与本帧后续查询一致，避免命中已死亡实体。

### 5.3 预测规则

- 初始显示第一段，直到首次碰撞，不显示反射后的第二段。
- 初级/中级/高级芯片分别额外显示 1/2/4 次反射；“段数 = 可见反射次数 + 1”。
- 同时限制总预测长度，不能无限延长。
- 预测必须使用当前武器速度、剩余寿命、最大反弹次数、护盾规则和碰撞层。
- 普通敌人默认吸收弹丸，因此预览到敌人终止；护盾正面继续显示反射路线。
- 霰弹首版显示中心方向；子母弹显示主弹直到首次分裂位置，并明确标记“分裂后未预测”。
- 预览只表达几何路线，不预测随机暴击、闪避、击杀分裂和后续敌人行动。

`TrajectorySolver` 提供无副作用的查询与命中分类接口，预览不能调用真实伤害/掉落逻辑。鼠标或装备变化时标记预览需要更新，在下一物理帧计算，以 `Line2D` 或自定义绘制显示结果。

### 5.4 初始安全上限

| 参数 | 建议值 |
| --- | --- |
| 基础弹速 | 900 像素/秒 |
| 玩家弹丸寿命 | 4 秒 |
| 手枪反弹次数 | 6 |
| 敌方弹丸反弹次数 | 1 |
| 同屏弹丸上限 | 128，所有阵营共享 |
| 分裂深度 | 2 |
| 每次玩家发射累计生成上限 | 256 |
| 单弹丸单帧碰撞循环 | 8 |
| 初始预测总长度 | 1200 像素 |

触发上限时按固定顺序抑制额外弹丸，不能允许延迟生成绕过预算。子弹派生链共享一次发射的预算；先登记子弹与待生成任务，再注销父弹，避免回合提前结束。

## 6. 障碍物与随机地图

三种基础障碍物均不可破坏，单回合中静止：矩形制造直角通道，圆形改变局部反射角度，三角形提供倾斜反射面。数据包含形状、尺寸、位置和旋转角度。

生成采用**模板约束 + 随机扰动 + 验证**，不完全随机堆放。

1. 根据关卡选择布局模板、障碍物数量和敌人组合。
2. 保留玩家安全区和若干通道，随机生成障碍物，检查边界及形状间距。
3. 生成敌人，排除与墙壁、障碍物、其他敌人重叠。
4. 等待物理碰撞同步，再从枪口扫描候选角度，使用实际武器规则验证攻击路线。
5. 验证护盾敌人存在可受伤角度；逐步模拟移除可击杀敌人，检查是否仍可推进。
6. 验证失败则重试，最多 30 次；仍失败则使用已验证的保底模板。

有限角度采样只能提供近似可达性检查，不能证明完整可解。首版应使用经过人工验证的模板，并要求每个敌人在当前两把武器中至少有一把存在可造成伤害的路线；装备破盾不能成为普通随机图的必要前提。

记录随机种子、生成尝试次数、失败原因，便于复现。预留“可达路线宽度”指标，避免只有极窄角度能命中的关卡。高密度布局应有数量上限，不能仅随关数无限加障碍物。

## 7. 敌人、武器和构筑

### 7.1 敌人

| 类型 | 规则 | 战术意义 |
| --- | --- | --- |
| 普通敌人 | 静止、受伤、死亡掉落，无主动攻击 | 教学目标、连锁目标 |
| 护盾反弹敌人 | 定向护盾，正面反射，背面可伤害 | 鼓励绕射和角度规划 |
| 射击敌人 | 每回合预警后朝玩家发射一轮 | 优先击杀、减少回合数 |

护盾建议覆盖正面 120°，以命中点相对敌人中心的方向判断，不直接用弹丸朝向替代。护盾朝向在瞄准阶段保持稳定。

敌方攻击可能被墙壁反射或障碍物阻挡，实际命中才造成伤害。固定站位下无法靠移动躲避，所以预警用于说明攻击来源和帮助下一回合决策；玩家的主要防御是优先击杀、利用障碍物、护甲和装备闪避。

完整版本 Boss 建议分别突出：护盾弱点、改变反射结构、召唤与混合威胁、综合机制。移动障碍物只在回合边界发生，瞄准开始后固定布局，保证预览可信。

### 7.2 武器

| 武器 | 初始建议 | 构筑方向 |
| --- | --- | --- |
| 手枪 | 1 发，20 伤害，6 次反弹 | 精准、暴击、反弹增伤 |
| 霰弹枪 | 5 发，每发 7 伤害，30° 扇形，4 次反弹 | 覆盖、多命中触发 |
| 子母弹枪 | 主弹 12 伤害，第 2 次反弹后分裂为 3 发，每发 6 伤害 | 分裂、清场、连锁 |

子母弹触发分裂后主弹消失；子弹继承剩余寿命和已用反弹次数，避免分裂不断重置寿命。MVP 子弹不再主动分裂，额外深度由后续道具明确解锁。

最多携带 2 把武器，品质和强化等级相互独立。购买第三把时先选替换对象，取消选择不扣钱。升级和词条以基础数据计算有效属性，避免重复叠加污染资源。

### 7.3 道具和效果

| 类别 | 示例 | 叠加约束 |
| --- | --- | --- |
| 预测 | 预测芯片、远距镜 | 段数与长度分别计算 |
| 输出 | 增伤、暴击、反弹增伤 | 暴击率不超过 100%，反弹增伤有上限 |
| 生存 | 最大生命、护甲、治疗 | 治疗不超过最大生命 |
| 闪避 | 幻影模块 | 建议概率上限 60% |
| 机制 | 穿透、分裂、吸血、连锁 | 明确每弹/每回合触发次数 |

推荐四条流派：反弹暴击、弹幕覆盖、连锁分裂、高生存消耗。MVP 每条流派至少提供两个能协同的道具，不必一次填满物品池。

伤害建议顺序：基础与固定加成 → 增伤倍率 → 有上限的反弹倍率 → 暴击 → 目标护甲 → 闪避判定 → 扣血 → 吸血/击杀事件。每个效果声明触发事件、叠加方式、作用对象和次数预算。

## 8. 商店、经济与难度

敌人金币和概率掉落直接进入本局库存或待领取奖励，不需要移动拾取。可用动画表现飞向 HUD。重复掉落按商品规则处理；武器溢出进入奖励选择，不能静默覆盖已有武器。

商店每次提供 4 商品位，至少一个可负担的固定价治疗选项，剩余位置从武器、道具、强化服务抽取。购买事务先验证金币与装备槽，再扣费与应用效果，防止重复点击扣款。

建议初始金币 0；普通/护盾/射击敌人分别奖励 5/8/10；清场奖励 10；恢复 25 生命售价 15；刷新费用本次商店按 5、10、15……递增，下一商店重置。普通道具价格可从 20 起，武器 35 起，随后依据品质与阶段调整。

原稿品质概率图未提供可读取数值，下表为补充的初始方案：

| 关卡 | 普通 | 优秀 | 稀有 | 史诗 | 传说 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1–5 | 60% | 30% | 10% | 0% | 0% |
| 6–10 | 35% | 35% | 23% | 6% | 1% |
| 11–15 | 20% | 30% | 30% | 16% | 4% |
| 16–20 | 10% | 20% | 35% | 25% | 10% |

先确定商品类型，再抽品质，再从符合条件的物品池中选择；没有对应品质物品时向下回退。避免抽到未实现或不满足条件的物品。首版 5 关使用第一阶段概率，另设测试入口验证高品质效果。

难度同时调节敌人类型、数量、有效射击角度、障碍物复杂度和反击强度。不要把所有参数同时大幅提升。初始生命 100，生命跨关继承。

精准奖励按布局模板的目标射击次数计算，无伤奖励以实际生命损失为准，连杀按一次玩家发射的派生链统计。奖励上限固定，不能通过治疗后再扣血或反复触发事件刷金币。

```text
   └─ ResultPanel
```

`RunState` 保存本局生命、金币、关数、武器实例、道具和统计；`RunController` 决定流程；`ProjectileManager` 管理弹丸与预算；`EffectSystem` 响应战斗事件；UI 通过信号显示状态，不直接修改战斗数值。

静态几何使用 `StaticBody2D + CollisionShape2D/CollisionPolygon2D`。射线弹丸可使用 `Node2D`，敌人使用可被射线命中的碰撞体；静止玩家也提供碰撞形状。不要用子弹间碰撞制造无关物理反馈。

| 碰撞层 | 用途 |
| --- | --- |
| 1 | 边界与障碍物 |
| 2 | 敌人及护盾目标 |
| 3 | 玩家 |

友方射线查询层 1+2；敌方和被护盾转为敌对的弹丸查询层 1+3。弹丸自身不必加入碰撞层。护盾命中由统一目标规则分类。

### 9.3 数据与随机数

自定义 `Resource` 存基础配置：`WeaponData`、`EnemyData`、`ItemData`、`StageConfig`。运行实例单独保存等级、已抽词条和临时状态，不能修改共享 `.tres` 数据。

所有物品使用稳定 ID，效果使用枚举或明确类型。配置加载时验证价格非负、权重总和有效、寿命与弹速为正、分裂参数符合上限。

用 `RandomNumberGenerator` 管理随机数，区分地图、商店、战斗、视觉随机流，防止新增粒子特效改变商店结果。保存种子用于复现；如果实现局内继续，还需保存各随机流状态。

### 9.4 存档与性能

MVP 在 `user://` 保存设置和局后统计，包含版本号，加载失败回退默认值。完整版本局内存档只在商店或瞄准等稳定节点保存，不序列化飞行中弹丸；存档字段包含关卡布局、生命、装备、金币和随机状态。

先采用清晰的弹丸节点管理，观察峰值耗时后再引入对象池。限制预测射线数量、弹丸数量、同帧连锁次数和特效数量；不让视觉优化改变战斗规则。

## 10. UI、视觉与反馈

HUD 显示生命、金币、关卡、当前武器、预测等级和阶段提示。玩家弹丸建议亮青色、敌方弹丸红橙色、预测线浅色虚线；颜色之外再用形状、线型区分。

护盾必须标出覆盖弧和弱点方向；反射点显示短促火花；暴击、分裂和穿透提供清晰反馈。大量粒子不可遮挡轨迹。

商店遮罩降低背景亮度，商品卡显示价格、品质、效果与叠加限制。武器替换显示前后属性。UI 消费鼠标输入，点击按钮不能穿透成射击。暂停时战斗停止，但暂停菜单仍能响应输入。

结局展示达到关数、射击次数、击杀数、总伤害、单弹最高伤害、单次发射最高伤害与最终构筑，避免“单发”在分裂武器中含义不清。

## 11. 分阶段实现流程与验收

### 阶段一：验证弹射手感

建立主场景、固定战场、枪口与鼠标瞄准；实现手枪、三种障碍物和一段预览。先用固定布局验证，不引入地图随机化。

**验收：**不同角度命中三种表面均正确反射；高速弹丸不穿墙；角点不死循环；预览折点与实际轨迹在相同静态布局中吻合。

### 阶段二：形成战斗回合

实现状态机、普通敌人、射击敌人、护盾敌人、敌方预警、生命伤害、死亡重开和弹丸注册表。

**验收：**连点不会重复发射；瞄准期间不受持续反击；每个存活攻击者只行动一次；最后一名敌人死亡不提前开店；护盾反弹能威胁玩家。

### 阶段三：形成武器与成长

接入资源数据、两武器槽、霰弹和子母弹、预测升级及一组基础道具，建立效果预算。

**验收：**切枪立即更新预览；分裂不重置寿命；派生弹不会提前结束回合；极端组合遵守数量上限；同一个资源的两把武器实例互不污染。

### 阶段四：打通五关与商店

实现模板生成、布局验证、保底图、掉落结算、4 位商店、治疗、刷新、强化和胜利统计。

**验收：**能从第一关完整玩到第五关胜利；余额不足不会购买；第三把武器需明确替换；无法通过验证的地图能有界回退；新局清空旧局装备和金币。

### 阶段五：验证平衡并完善交付

完成 HUD、音效、预警、设置存档和诊断日志，收集每关射击次数、失血、金币收入、消费、刷新次数和预测道具购买率。

**验收：**新手能理解反弹与护盾弱点；至少两种构筑可通过 MVP；治疗具有实际可负担性；最大弹丸预算下回合仍能结束，目标设备帧率稳定。

### 阶段六：扩展完整版本

在核心闭环稳定后扩到 20 关、4 Boss、高品质机制和特殊障碍物。每新增一个机制都补充其预览规则、地图验证规则和触发预算；不要先扩内容再补规则。

## 12. 关键测试与调试工具

| 测试 | 重点 |
| --- | --- |
| 确定性弹道场景 | 平墙、斜面、圆切线、角点、多次反弹 |
| 预测/运行对照 | 同一武器与起点，检查碰撞点、方向和结束原因 |
| 状态转换测试 | 连点、最后击杀、反射自伤、暂停、分裂、死亡清理 |
| 效果组合压力测试 | 分裂+连锁+额外弹丸，验证全局及单次发射预算 |
| 生成批量检查 | 至少 1000 个固定种子，统计失败与保底率；抽样人工试玩 |
| 经济检查 | 收入可购买有意义的升级，低血量时仍可治疗 |
| 存档检查 | 损坏文件、缺失字段、版本变更回退 |

提供开发面板：显示种子、当前状态、活跃弹丸数、待生成任务数、法线、有效路线和预算拒绝次数。允许跳关、给予道具和复现种子，减少调试成本。

## 13. 开发前优先确认与试玩问题

以下采用本文默认值即可启动开发，随后通过原型调整：

1. 护盾转敌对弹丸的危险程度是否容易理解，是否需要更明显的变色和音效。
2. 初始只有一段预测是否过难；优先用关卡一教学和清晰几何降低门槛，再决定是否赠送初级芯片。
3. 4 秒弹丸寿命是否使回合过长；如增加快进，必须加速同一模拟过程，不能改变路径结果。
4. 固定站位下敌人攻击是否提供足够策略空间，是否需要少量次数的主动防御作为后续机制。
5. 品质升级是否真正改变策略；传说效果应改变行为，不能只增加数值。

项目推进顺序为：**先证明反弹有趣且预测可信，再打通五关闭环，最后扩展随机内容和完整构筑。**
